## Ⅲ. 측정 결과

### 1. 종합 비교

| 항목 | rhwp | kordoc | 판정 |
|---|---:|---:|---|
| 성공 | 135 / 135 (100%) | 135 / 135 (100%) | 동일 |
| 실패 | 0 | 0 | 동일 |
| 평균 소요 | **20.2 ms** | 341.7 ms | rhwp **17배 빠름** |
| 중앙값(p50) | **17.4 ms** | 326.3 ms | |
| 최대 | **63.4 ms** | 508.5 ms | |
| 품질게이트 통과 | 133 / 135 (98.5%) | 134 / 135 (99.3%) | 유사 |
| 평균 마크다운 길이 | 2,525자 | 4,070자 | 아래 2항 참조 |
| 평균 표 인식 수 | **2.47개** | 0.58개 | rhwp **4.3배** |

### 2. 마크다운 길이가 긴 것이 우수한 것은 아님

- □ kordoc 산출물이 1.6배 길지만 **표 인식은 1/4 수준**임
- □ 길이 차이의 실체는 결재표·머리말 등 **정형 노이즈를 본문으로 흘린 것**임
  - ○ 표를 표로 인식하지 못하고 텍스트로 나열하면 글자 수는 늘지만 구조가 소실됨
- □ 검색 관점에서는 표 구조 보존이 중요하므로 rhwp 가 우위임

### 3. 품질게이트 탈락 사례 (rhwp 2건)

| 파일 | 사유 | 실측 밀도 |
|---|---|---:|
| 1.교원 업적평가 시행안내(2026 상반기).hwp | `G1_DENSITY` | 0.000851 |
| 2026년 한국공학대학교 개인정보 청소하는 날 캠페인 실시.hwp | `G1_DENSITY` | 0.000902 |

- □ 성격: **오탐**. 두 건 모두 이미지 비중이 큰 안내문으로, 텍스트 밀도가 낮은 것이 정상임
  - ○ 예: 2,772KB 파일에서 마크다운 2,360자 → 밀도 0.000851
- □ 조치: 임계값을 `0.001` → **`0.0005`** 로 완화함 (`QG_DENSITY_THRESHOLD`)
  - ○ 완화 후 두 건 모두 통과함
- □ 게이트 모드는 `log` 로 운영함 — 탈락해도 색인은 진행하되 경고만 남김
  - ○ 사유: 오탐으로 문서를 버리는 손실이, 저품질 문서를 색인하는 손실보다 큼

## Ⅳ. 채택 결정

### 1. 결론

- □ **rhwp (PyO3 네이티브) 채택**, kordoc 폐기

### 2. 근거

- ○ 표 인식률이 4.3배 높음 — 공문은 표 비중이 크므로 결정적 차이임
- ○ 처리 속도 17배 — 1,200건 전량 파싱 시 24초 vs 7분의 차이
- ○ 성공률·게이트 통과율은 실질적 차이 없음(각각 100%, 98.5% vs 99.3%)

### 3. 구현 반영

- □ `.hwp` → rhwp (PyO3 네이티브)
- □ `.hwpx` → python-hwpx (순수 파이썬)
  - ○ HWPX 는 ZIP+XML 구조라 네이티브 확장 없이 읽힘
  - ○ **rhwp 의 네이티브 ABI 리스크에서 분리**하는 것이 목적임
  - ○ HWPX 엔진 부재 시 rhwp 로 자동 대체(fallback)
- □ 관련 코드: [`services/parser/engine.py`](../services/parser/engine.py)


## Ⅵ. 제약 및 미검증 항목

- □ **암호 걸린 HWP**: 표본에 없어 미검증
- □ **구버전 HWP(v3 이하)**: 표본에 없어 미검증
- □ **HWPX 표본 부족**: 135건 중 1건뿐이라 HWPX 경로는 통계적 근거가 약함
  - ○ 운영 코퍼스에는 26건 존재하며 전량 색인 성공했으나, 품질은 별도 측정하지 않음
- □ **표 인식 정확도**: 표 "개수"만 셌고, 셀 병합·중첩 표의 정확도는 측정하지 않음
