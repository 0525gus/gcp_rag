# 2 vCPU 및 FactChat 동시 40개 검증 — 2026-09-11 KST

통합 MCP를 **2 vCPU / 1 GiB**로 변경하고 `rag-mcp-cpu2-prod-0911b`에 트래픽 100%를
전환했다. 동시 요청 설정은 40, 서비스·리비전 최소 인스턴스는 모두 0이다.
`config/common.yaml`의 `MCP_CPU`도 2로 갱신했다. 공통 MCP URI는 동일하다.

## 실제 FactChat 경로

- 교직원: `https://factchat-cloud.mindlogic.ai/v1/gateway/chatbots/51767/chat/completions`
- 학생: `https://factchat-cloud.mindlogic.ai/v1/gateway/chatbots/51766/chat/completions`

FactChat 챗봇 API에 독립적인 스트리밍 대화를 요청했다. MCP 직접 호출 부하 테스트가 아니다.
먼저 챗봇에 고유 검증 식별자를 포함한 검색을 요청하고, Cloud 로그에서 해당 식별자가
새 2 vCPU 리비전에 도착한 것을 확인했다. 응답 본문과 키는 보고서에 저장하지 않았다.

학생 챗봇은 처음에는 HTTP 403을 반환했다. 사용자가 접근을 해제한 뒤 같은 키로
정상 연결 및 목표 리비전 호출을 확인하고 **학생 챗봇도 별도로 동시 40개를 테스트**했다.
교직원·학생 각각 40개인 두 차례 실험이며 혼합 동시 80개 실험은 아니다.

## 교직원 결과

| 항목 | 결과 |
|---|---:|
| 동시에 보낸 대화 요청 | 40 |
| 정상 스트리밍 완료 | 29 |
| FactChat API HTTP 429 | 11 (27.5%) |
| 성공 요청 첫 답변 중앙값 / p95 | 9.239초 / 12.615초 |
| 성공 요청 전체 완료 중앙값 / p95 | 11.507초 / 15.169초 |
| 성공 요청 전체 완료 최댓값 | 16.285초 |

429 응답은 약 0.33–0.36초에 반환됐다. 실패를 감추지 않도록 자동 재시도는 하지 않았다.
성공은 HTTP 200, 텍스트 수신, 스트림 종료를 뜻하며 답변 내용의 정확성 평가를 뜻하지 않는다.

성공 대화 **29개 모두** 고유 검색 식별자로 2 vCPU 리비전 호출을 확인했다.
429 요청 11개에서는 검색 식별자가 관측되지 않았다. 사전 확인을 포함한 검색 로그
36개는 모두 `rag-mcp-cpu2-prod-0911b`에서 발생했다. 일부 대화는 여러 번 검색했다.

부하 구간의 MCP HTTP 로그는 200이 70건, 202가 35건이고 오류 응답은 없었다.
이 집계에는 MCP 프로토콜 초기화·알림이 포함되며 대화 수와 같지 않다.
요청을 처리한 instanceId는 1개였다. FactChat 모델의 도구 호출 시점은 분산되므로
**FactChat 동시 대화 40개를 MCP 동시 검색 40개와 동일하게 해석하면 안 된다.**

## 판단 및 현재 상태

학생 재검증은 40개 중 정상 완료 29개, FactChat HTTP 429 11개(27.5%)였다.
성공 요청의 첫 답변 중앙값/p95는 6.926초/9.652초, 전체 완료 중앙값/p95는
13.316초/16.924초, 최댓값은 27.487초였다.
성공 대화 29개 모두 고유 식별자로 목표 2 vCPU 리비전 호출을 확인했고, 429 대화의
식별자는 MCP 검색 로그에서 관측되지 않았다. 사전 확인 포함 검색 로그 38개가
모두 목표 리비전에 기록됐다. 해당 구간 MCP POST 응답은 200 74건, 202 37건으로
HTTP 오류는 없었고 요청을 처리한 instanceId는 1개였다.

이번 실패는 FactChat API의 요청 제한(429)에서 발생했다. 정확한 제한 단위가 동시성인지
분당 요청량인지는 확인되지 않았다. CPU만 늘려 이 제한을 해결할 수는 없으므로 FactChat의
호출 한도 확인 및 백오프 재시도를 검토해야 한다. 기존 1 vCPU 직접 MCP 테스트와는
경로·부하 형태가 달라 속도 향상률을 계산하지 않았다.

테스트 이후 `/health` 200과 운영 트래픽 100%, 2 vCPU / 1 GiB / min 0을 재확인했다.
Ruff와 `git diff --check`가 통과했다. API 키를 전달하는 데 사용한 임시 파일은 삭제했다.

- [교직원 40개 원시 집계 및 백엔드 대조](factchat-cpu2-staff40.json)
- [교직원·학생 사전 점검 및 학생 403](factchat-cpu2-load.json)
- [접근 해제 후 학생 40개 결과](factchat-cpu2-student40.json)

재실행은 `scripts/load_test_factchat.py --audience staff --revision <리비전> --out <보고서>`를
사용한다. 키는 `FACTCHAT_API_KEY` 환경변수 또는 `--key-file`로 전달한다. 키 원문을
명령행 인자로 전달하지 않는다. 사전 점검이 실패하거나 목표 리비전 호출을 확인하지 못하면
40개 대화를 보내지 않는다.
