## Ⅱ. 발견 및 조치

### 1. MCP 검색 엔드포인트가 인증 없이 공개됨 〔심각〕

#### 가. 현상

- □ API 키 없이 외부에서 호출 시 **코퍼스 전체가 검색됨**
- □ 검증: 인증 헤더 없이 요청 → 학사경고자 명단 문서가 정상 반환됨

#### 나. 원인

- □ 두 조건이 동시에 성립함

| 항목 | 상태 |
|---|---|
| Cloud Run 호출 권한 | `allUsers` (인터넷 공개) |
| `MCP_API_KEY` 환경변수 | **미설정** |

- □ 애플리케이션 게이트는 키가 없으면 **검사를 건너뛰도록** 구현되어 있음
  ([`services/mcp_server/main.py`](../services/mcp_server/main.py))

#### 다. 발생 경위

- □ 리비전 이력 추적 결과

| 리비전 | 일시 | 키 |
|---|---|---|
| 00002 ~ 00004 | 7/23 ~ 7/24 | 설정됨 |
| **00005** | **7/25 14:01** | **유실** |
| 00006 ~ 00013 | 7/25 ~ 7/28 | 없음 |

- □ 배포 스크립트는 키를 필수로 강제하나, 해당 리비전들은 스크립트를 경유하지 않음
- □ 노출 기간 **약 3일**, 노출 대상은 명단·인사발령·개인정보 관리계획 등 전 문서

#### 라. 조치

- □ 리비전 00004 에서 원래 키 값을 확인하여 **동일 값으로 복원**함 (리비전 00014)
  - ○ 신규 키 발급 시 FactChat 커넥터가 중단되므로 기존 값을 사용함
  - ○ `--update-env-vars` 사용하여 기존 검색 설정값을 보존함

#### 마. 검증

```
키 없음      → HTTP 401
잘못된 키    → HTTP 401
정상 키      → HTTP 200 (정상 검색)
X-API-Key 경로 → HTTP 200
```

#### 바. 부작용 — FactChat 연동 일시 중단

- □ 키를 켠 직후 FactChat 커넥터가 **인증 실패**로 중단됨

```
[TOOL_ERROR] Authentication failed for connector__chatbot_mcp_custom_2741__search.
The saved token may be expired or revoked — please update this connector's Authorization header.
```

- □ 원인: **커넥터에 저장된 토큰이 복원한 키와 달랐음**
  - ○ 조치 전 판단: 리비전 00002~00004에 있던 키를 FactChat도 쓰고 있을 것으로
    **추정**하고 진행했음
  - ○ 실제로는 7/25 키 유실 이후 인증이 무력화된 상태로 운영되어,
    커넥터 토큰이 현재 키와 일치하는지 확인되지 않았음
- □ **점검 절차상의 누락**: 키를 활성화하기 전에 클라이언트가 실제로 보내는
  인증 헤더를 확인했어야 함(rag-mcp 접근 로그로 확인 가능)
- □ 복구: FactChat 커넥터의 Authorization 헤더를 현재 키로 갱신
- □ 교훈: **인증을 켜는 변경은 서버 단독으로 완결되지 않음.**
  클라이언트 설정과 동시에 처리하거나, 최소한 클라이언트가 보내는 값을
  먼저 확인해야 함

### 2. 일일 동기화 3일간 중단 〔주의〕

#### 가. 현상

- □ Cloud Scheduler 상태 `ENABLED`, 매일 정시 발사되었으나 **매회 실패**함

```
2026-07-27 15:00  ERROR INVALID_ARGUMENT
2026-07-26 15:00  ERROR INVALID_ARGUMENT
2026-07-25 15:00  ERROR INVALID_ARGUMENT
```

#### 나. 원인

- □ 스케줄러 요청 본문의 **JSON 이스케이프 오류**

```
{"argument":"{\"syncUrl\":\"...\",\"driveIds\":["0AP6Mv9od5B3yUk9PVA"]}"}
                                              └─ 이스케이프 누락
```

- □ `driveIds` 배열 내부 따옴표가 이스케이프되지 않아 문자열이 조기 종료됨
  → 바깥 JSON 파싱 실패 → HTTP 400
- □ `Content-Type` 이 `application/octet-stream` 으로 설정된 문제도 함께 확인됨

#### 다. 영향

- □ **실제 유실 문서 없음**
  - ○ 색인된 문서의 최신 Drive 수정시각이 **2026-07-22** 로, 중단 기간에 신규 문서가 없었음
  - ○ 문서 상태에도 `FAILED 0 / PENDING 0` 으로 누락 흔적 없음
- □ 다만 **잠복 결함**이었음 — 문서가 등록되는 즉시 조용히 누락되는 상태였음

#### 라. 조치 및 검증

- □ 페이로드 이스케이프 수정, `Content-Type: application/json` 으로 변경
- □ 수동 발사하여 **실제 완주 확인**

```
상태 SUCCEEDED (18초)
결과 listed 10 / skipped 6 / unchanged 4 / failed 0 / dlq 0
```

## Ⅴ. 점검을 통해 확인된 구조적 시사점

### 1. 장애가 겉으로 드러나지 않음

- □ 발견된 3건 모두 **관제 화면상으로는 정상**이었음
  - ○ 스케줄러 `ENABLED`, 워크플로 존재, Cloud Run 정상 기동 상태에서 실제로는 HTTP 400 반복
- □ **알림이 하나도 설정되어 있지 않음**이 근본 원인임
  - ○ 알림 정책 0 / 로그 기반 지표 0 / 알림 채널 0
- □ 운영 전환 시 최소 2종 필요

| 알림 | 목적 |
|---|---|
| Cloud Scheduler 실행 실패 | 동기화 중단 감지 |
| Cloud Run 5xx 비율 | 서비스 장애 감지 |

### 2. 배포 경로 이원화가 설정 유실을 유발함

- □ 배포 스크립트는 필수값을 강제하나, `gcloud run services update` 직접 실행 시 우회됨
- □ `--set-env-vars` 는 기존 환경변수를 **치환**하므로 누락 시 조용히 사라짐
- □ 대책
  - ○ 단기: `--update-env-vars`(누적)만 사용
  - ○ 근본: 키를 Secret Manager 로 이관하면 환경변수 갱신과 분리되어 유실 경로가 사라짐
